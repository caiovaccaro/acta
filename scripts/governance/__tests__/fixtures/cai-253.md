## OpenSpec

**Change ID:** `p1-09-transactional-llm-budget`
**Depends on:** P1-08

## Problem

Concurrent or long-running LLM work can exceed a log-only monthly budget.

## Required behavior

Reserve conservative cost before each request, reject over-budget work, settle actual usage, expire abandoned reservations safely, and expose remaining budget.

## Interfaces

`LlmBudgetReservation`, budget guard API, and a USD 30 monthly application ceiling.

## Failure, security, and cost

Uncertain reservations remain conservative until their owner lease is stale. Arithmetic uses fixed precision. The application ceiling cannot be raised by untrusted CLI input.

## Out of scope

Provider billing configuration.

## Given/When/Then test specification

### Unit

GIVEN reservations across precision and month-boundary cases, WHEN reserve, settle, or expire executes, THEN available budget is conservative and correct.

### Integration

GIVEN concurrent PostgreSQL reservation attempts near the ceiling, WHEN transactions commit, THEN total settled plus reserved cost never exceeds the limit.

### E2E

GIVEN a low test ceiling, WHEN a slice exhausts it, THEN paid stages pause, deterministic stages continue, and the run reports `paused_budget`.

## Acceptance criteria

- [ ] Concurrent calls cannot reserve over USD 30.
- [ ] Failed calls settle or expire predictably.
- [ ] Expensive stages pause when budget is unavailable.
- [ ] OpenSpec artifacts are valid and synchronized with this issue.
- [ ] Unit, concurrent integration, budget-exhaustion E2E, and regression tests pass.
- [ ] `/opsx:verify` and commit-bound `verify:pr-ready` pass before PR creation.

None.
