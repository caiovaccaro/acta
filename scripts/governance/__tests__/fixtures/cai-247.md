## OpenSpec

**Change ID:** `p1-01-linux-ci-config-validation`
**Depends on:** P1-00

## Problem

The project has no repeatable Linux verification or complete production configuration contract.

## Required behavior

Install deterministically, generate Prisma, validate non-secret configuration shape, run all test classes, and build the web app on Linux.

## Interfaces

CI workflow, production configuration validator, and canonical unit/integration/E2E/regression commands.

## Failure, security, and cost

Fail with variable names and actionable messages, never values. CI uses fixtures and service containers, not production credentials or paid provider calls.

## Out of scope

Production deployment.

## Given/When/Then test specification

### Unit

GIVEN missing or invalid production variables, WHEN configuration validation runs, THEN it reports variable names and constraints without values.

### Integration

GIVEN a clean workspace and CI PostgreSQL, WHEN installation, Prisma generation, and workspace tests run, THEN every package completes successfully.

### E2E

GIVEN a clean Linux runner, WHEN the canonical verification command runs, THEN it builds the web app and emits a successful commit-bound report.

## Acceptance criteria

- [ ] `npm ci`, Prisma generation, workspace tests, and web build pass on Linux.
- [ ] Missing production variables fail with names but never values.
- [ ] CI requires no production secrets.
- [ ] Unit, integration, and E2E commands are explicit and consumed by `verify:pr-ready`.
- [ ] OpenSpec artifacts are valid and synchronized with this issue.
- [ ] Unit, integration, E2E, and regression tests pass.
- [ ] `/opsx:verify` and commit-bound `verify:pr-ready` pass before PR creation.
- [ ] Post-open CI and adversarial review pass before merge.
