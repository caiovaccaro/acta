## OpenSpec

**Change ID:** `p1-10-tavily-basic-search`
**Depends on:** P1-05, P1-07

## Problem

The pipeline lacks a broad, current signal for choosing which work consumes capped extraction and LLM budget and for corroborating moderation.

## Required behavior

Execute bounded basic searches, normalize results, deduplicate URLs, persist trend signals, and degrade safely.

## Interfaces

Tavily client, five query groups, request cap, and `TrendSignal`.

## Failure, security, and cost

Timeout, malformed payload, empty results, or quota exhaustion do not block RSS processing. The API key remains secret, paid overage is disabled, and the daily request cap is explicit.

## Out of scope

Tavily content becoming direct verdict evidence or bypassing approved ingestion.

## Given/When/Then test specification

### Unit

GIVEN duplicate, malformed, and boundary Tavily results, WHEN normalization runs, THEN valid URLs, domains, scores, and request counts are deterministic and capped.

### Integration

GIVEN mocked Tavily success, timeout, malformed, empty, and quota responses, WHEN the client runs, THEN signals persist only when valid and failures return the specified degraded result.

### E2E

GIVEN a fixture daily trend stage, WHEN Tavily succeeds and later exhausts quota, THEN stored signals remain usable and the pipeline continues in degraded mode.

## Acceptance criteria

- [ ] Daily searches stay within the configured request cap.
- [ ] Empty, failed, and exhausted Tavily responses degrade safely.
- [ ] URLs and domains are deduplicated.
- [ ] OpenSpec artifacts are valid and synchronized with this issue.

None.
