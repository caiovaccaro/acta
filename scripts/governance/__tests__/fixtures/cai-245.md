## OpenSpec

**Change ID:** `p1-04-neon-production-validation-recovery`
**Depends on:** P1-03

## Problem

The existing Neon database needs repository-enforced migration safety, integrity verification, and tested recovery.

## Required behavior

Reuse canonical Neon, inspect it read-only, validate pooled/direct roles without values, verify integrity and recovery, fail closed on migrations, and reconfirm Vercel production data.

## Interfaces

Production database contract, integrity command, controlled migration, restore verification, and Vercel data check.

## Failure, security, and cost

Fail without credentials or private data, never run implicit production migrations, keep backup artifacts local, and use existing free-tier/disposable resources.

## Out of scope

Provisioning, replacing, or mutating production.

## Given/When/Then test specification

### Unit

GIVEN expected schema, migration, integrity, and connection-variable rules, WHEN validation runs against missing or malformed metadata, THEN it fails with actionable diagnostics that name the violated contract without exposing values.

### Integration

GIVEN a fresh logical backup of the existing Neon database and empty disposable PostgreSQL, WHEN restore and migration verification run, THEN the restored database reaches the current schema and passes required table, bounded row-count, and representative-ID checks without destructive drift.

### E2E

GIVEN the Vercel preview connected to the existing Neon database, WHEN health and representative public topic/question API checks run, THEN the database reports connected and both APIs return non-empty production data.

## Acceptance criteria

- [ ] Existing Neon remains canonical.
- [ ] Read-only inspection and restore verification pass.
- [ ] Explicit test classes and commit-bound readiness pass.
- [ ] Post-open checks pass.
