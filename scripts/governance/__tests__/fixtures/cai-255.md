## OpenSpec

**Change ID:** `p1-12-moderation-policy-shadow`
**Depends on:** P1-10, P1-11

## Problem

Auto-approval must be explainable, conservative, and testable before it mutates publication state.

## Required behavior

Evaluate every Level 1 condition, persist evidence and policy version, support shadow mode, and hold safety-sensitive candidates.

## Interfaces

Policy input/output contract and environment thresholds from the Phase 1 moderation policy.

## Failure, security, and cost

Missing, stale, or contradictory evidence produces a pending decision. Policy cannot bypass budget or public moderation filters.

## Out of scope

Enabling mutation in production.

## Given/When/Then test specification

### Unit

GIVEN each moderation condition at, above, and below its threshold, WHEN policy evaluation runs, THEN the decision and policy version explain every pass and failure.

### Integration

GIVEN real topic, article, outlet, and trend-signal records, WHEN shadow evaluation runs, THEN it stores an auditable proposal without mutating moderation status.

### E2E

GIVEN approval-ready, incomplete, duplicate, and safety-sensitive candidates, WHEN a shadow slice completes, THEN it proposes only the eligible approval and leaves every status unchanged.

## Acceptance criteria

- [ ] Every condition produces a stored result.
- [ ] Safety-sensitive or incomplete candidates stay pending.
- [ ] Shadow mode never mutates moderation status.
- [ ] OpenSpec artifacts are valid and synchronized with this issue.
- [ ] Unit, evidence integration, shadow-policy E2E, and regression tests pass.
- [ ] `/opsx:verify` and commit-bound `verify:pr-ready` pass before PR creation.
- [ ] Post-open CI and adversarial review pass before merge.

## Open questions

None.

Safety-sensitive classifier is a deterministic token list covering weapons, child sexual exploitation, suicide/self-harm, and violent extremism. Any match holds the candidate pending. Shadow mode never mutates status.
