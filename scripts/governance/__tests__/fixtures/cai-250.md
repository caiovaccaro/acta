## OpenSpec

**Change ID:** `p1-06-stable-cursors-bounded-stages`
**Depends on:** P1-02, P1-05

## Problem

Numeric offsets over mutating tables cannot safely resume multi-run work.

## Required behavior

Select stable `(createdAt, id)` windows, process bounded units, checkpoint only committed work, and stop claiming work near deadline.

## Interfaces

Stage-unit contract, cursor codec, per-stage limits, and deadline signal.

## Failure, security, and cost

A failed unit leaves its cursor unchanged. Deleted rows and equal timestamps do not skip later records. Unit caps are required in production.

## Out of scope

Cross-stage orchestration.

## Given/When/Then test specification

### Unit

GIVEN equal timestamps, deleted records, empty windows, and deadline boundaries, WHEN cursors advance, THEN ordering is stable and no uncommitted item is skipped.

### Integration

GIVEN a PostgreSQL dataset mutated between pages, WHEN bounded traversal completes, THEN each eligible record is committed exactly once.

### E2E

GIVEN a multi-page stage interrupted after a checkpoint, WHEN a new process resumes, THEN it reaches completion without duplicate domain writes.

## Acceptance criteria

- [ ] Every long stage checkpoints after bounded work.
- [ ] A restart resumes after the last committed unit.
- [ ] Cursor tests cover equal timestamps and deleted records.
