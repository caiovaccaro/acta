## OpenSpec

**Change ID:** `p1-13-operational-moderation-email`
**Depends on:** P1-07, P1-09, P1-12

## Problem

Autonomous runs require concise owner-visible outcomes without terminal monitoring.

## Required behavior

Send success, pause, failure, budget, and moderation digest messages with the fields defined in the Phase 1 notification contract.

## Interfaces

Resend adapter, notification service, templates, production links, and admin links.

## Failure, security, and cost

Email failure is recorded but never corrupts successful pipeline work. Redact secrets and sensitive payloads, aggregate messages, and remain within free quotas. The destination exists only in the `PIPELINE_EMAIL_TO` environment secret and must not appear in repository or ticket content.

## Out of scope

End-user newsletters. Retries, backoff, and intermediate emails. Skipping email does not disable budget enforcement.

## Given/When/Then test specification

### Unit

GIVEN success, pause, budget, moderation, and failure summaries containing sensitive values, WHEN templates render, THEN subjects, links, aggregates, and redaction match the specification.

### Integration

GIVEN mocked Resend acceptance, rejection, and timeout responses, WHEN notification delivery runs, THEN attempts and failures are recorded without corrupting pipeline state.

### E2E

GIVEN a successful fixture slice and a forced terminal failure, WHEN both finish, THEN the test transport receives one complete receipt for each outcome.

## Acceptance criteria

- [ ] Success, paused, and failed receipts are readable and actionable.
- [ ] Email failure does not corrupt pipeline state.
- [ ] Messages link to production and admin.
- [ ] OpenSpec artifacts are valid and synchronized with this issue.
- [ ] Unit, Resend integration, receipt E2E, and regression tests pass.
- [ ] `/opsx:verify` and commit-bound `verify:pr-ready` pass before PR creation.
- [ ] Post-open CI and adversarial review pass before merge.

## Open questions

None.

Sender identity is exclusively the `PIPELINE_EMAIL_FROM` environment secret on a Resend-verified domain. Tests use `Acta Pipeline <pipeline@example.invalid>`. The destination remains `PIPELINE_EMAIL_TO` as a secret only and is never copied into tickets, OpenSpec, logs, or fixtures.
