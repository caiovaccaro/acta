## OpenSpec

**Change ID:** `p1-16-moderation-shadow-evaluation`
**Depends on:** P1-12, P1-13, P1-14

## Problem

Auto-approval thresholds need production evidence before they mutate state.

## Required behavior

Collect at least seven successful daily shadow runs, classify proposed decisions, calculate false approvals and holds, and recommend thresholds.

## Interfaces

Evaluation dataset, decision rubric, and signed-off report attached to this ticket.

## Failure, security, and cost

Failed or incomplete runs do not count toward seven. Ambiguous human labels remain documented. Evaluation uses stored results and does not rerun paid calls unnecessarily.

## Out of scope

Enabling auto-approval.

## Given/When/Then test specification

### Unit

GIVEN labeled shadow decisions, WHEN evaluation metrics and report validation run, THEN false approvals, holds, and threshold summaries are correct.

### Integration

GIVEN stored decisions and owner labels, WHEN the evaluation report is built, THEN every included decision is traceable to evidence and policy version.

### E2E

GIVEN seven successful fixture daily runs, WHEN evaluation completes, THEN it emits a valid go/no-go recommendation with proposed thresholds.

## Acceptance criteria

- [ ] Proposed decisions are reviewed and classified.
- [ ] Threshold adjustments are documented.
- [ ] A go/no-go recommendation for Level 1 is produced.
- [ ] OpenSpec artifacts are valid and synchronized with this issue.
- [ ] Unit, report integration, seven-run evaluation E2E, and regression tests pass.
- [ ] `/opsx:verify` and commit-bound `verify:pr-ready` pass before PR creation.
- [ ] Post-open CI and adversarial review pass before merge.

## Open questions

None.

Acceptable false-approval tolerance for Level 1 enablement is zero in the evaluation sample. Any false approval is a no-go. False holds stay documented and do not block a conservative go.
